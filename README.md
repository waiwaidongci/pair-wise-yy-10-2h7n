# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用。

已实现闭环：
- 新增作品并记录胎体、纹样、线条、贴线进度、阴干日期、金粉状态、缺陷和交付日期。
- 工序看板覆盖贴线中、待阴干、上金粉、待交付。
- 今日待阴干、缺陷作品、最近交付三类列表。
- 可更新状态、记录断线/翘线、查看作品详情。
- 支持筛选、交付排序、localStorage 持久化和 JSON 导出。

## 上金粉闸：金箔批次领用与扫粉核销

判定、存档、页面分属三块独立部分，页面不自行解释任何阈值：

- `js/gold-rules.js` — 判定（纯函数，不碰 DOM 与存储）。
- `js/gold-store.js` — 存档（localStorage 持久化、append-only 履历、投递去重）。
- `js/gold-ui.js` — 页面（领用表单、列表操作、履历展示）。

闸口规则：

1. 同批号未核销前只服务一件作品：批号被「已领用 / 待复核」单占用时，其他作品整单退回。
2. 领用克数、扫粉室温、操作者（与批号、作品）任一不齐，整单退回，不生成订单也不留履历（不留半截单）。
3. 扫粉后按称重核销：实耗与领用相差 ≤ 3% 直接核销；超过 3% 只进待复核。
4. 待复核单必须由他人复核：复核人不得与操作者相同。
5. 批号或克数更正后，原核销（含原复核结论）作废、清称重记录，回到已领用按新值重算；仅改室温/操作者不影响核销结论。
6. 重复投递认首次结果：同一请求编号只生效一次，后续重复提交原样返回首次结论（含首次退回）。
7. 列表与履历同读一份存档，刷新或重开页面后保持一致；履历只追加、不覆盖，作废有独立留痕。

# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用。

已实现闭环：
- 新增作品并记录胎体、纹样、线条、贴线进度、阴干日期、金粉状态、缺陷和交付日期。
- 工序看板覆盖贴线中、待阴干、上金粉、待交付。
- 今日待阴干、缺陷作品、最近交付三类列表。
- 可更新状态、记录断线/翘线、查看作品详情。
- 支持筛选、交付排序、localStorage 持久化和 JSON 导出。

## 上金粉 · 金箔批次领用与扫粉核销闸

新增功能分属三块相互独立的部分（各文件可单独阅读、测试、替换）：

| 部分 | 文件 | 职责边界 |
| --- | --- | --- |
| 判定 | `gold/rules.js` | 纯函数规则，不碰 DOM、不碰存储，可在 Node 直接 `require` 测试 |
| 存档 | `gold/store.js` | 台账与履历持久化、幂等令牌、原子写入，不碰 DOM |
| 页面 | `gold/ui.js` | DOM 编排与事件，规则查判定层、读写查存档层 |

台账数据存于 localStorage 键 `zfl42GoldLedger`（`records[]` + 幂等令牌表），
列表与全局履历都读同一份快照；刷新页面或点“重读存档”后两者保持一致。

业务规则：

1. **同批号未核销前只服务一件作品** —— 批号在“待核销/待复核”期间被占用，
   已核销后可再领给其他作品；更正批号同样受此约束。
2. **整单退回，不留半截单** —— 批号、领用克数、扫粉室温、操作者、作品任一缺失
   或非法，整单拒绝且不写盘；成功才一次性持久化。
3. **扫粉后按称重核销** —— `|实耗 − 领用| / 领用 ≤ 3%` 自动核销；
   **超过 3% 只进待复核**（偏差按 0.001% 精度取整，规避浮点尾差）。
4. **复核人不得与操作者相同**，复核通过才转为已核销。
5. **批号或克数更正后原核销作废并按新值重算**：保留实称克数重新走 3% 判定，
   原复核结论一并作废（复核人清空）；未称重的单回到待核销。
6. **重复投递认首次结果** —— 每次操作携带幂等令牌，同令牌再次提交直接返回首次结果，
   不重复建单/核销/更正；失败不占用令牌，修正后可用同令牌重试。

测试：

```bash
node gold/test.js          # 判定层 + 存档层 31 项规则/存档验收
```
